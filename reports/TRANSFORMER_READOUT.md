# 原始 Transformer 实验结果解读

**在原始 Transformer/AKT 上，方向一有小幅、有限的正向结果；方向二没有带来额外 AUC 提升，但改善了难度一致性和冷启动下的部分概率质量指标。** 这次完成了原始模型、静态语义题目参数、静态参数加难度对齐三组模型，在 warm、cold 两种协议下各跑 42、2026、3407 三个种子，共 18 次正式训练。

**这次具体改了什么。** 三组都保留你原来的 `TextAKT3PL`：2 个 blocks、8 个 attention heads、128 维隐藏状态，均为 **2,591,164 个可训练参数**。同一种子的参数初始化相同，训练规则相同。原始 256 维题干向量和 256 维知识点向量保持固定，模型仍可学习原有的语义投影层，没有新增可训练题目、知识点或学生 ID 向量。

方向一的 `static` 只改变三个题目参数头读取的特征。用大白话说，原来模型在估计“这道题有多难、区分度多高、猜对概率多大”时，也会看到题目所在的位置以及前面出现过的题；现在让这三个参数只看当前题目的语义。相同题目无论放在什么位置，都得到相同的题目参数。

```text
共同步骤：s = 题干语义投影 + 知识点语义投影
          f = 原有上下文 Transformer(s + 位置编码)

原始模型：mu / alpha / guess 三个参数头读取 f
static：  mu / alpha / guess 三个参数头读取 s
```

原有的上下文特征 `f` 仍进入交互表示与 AKT；位置编码、注意力层、题目参数参与的交互门控、能力预测头和 3PL 输出公式都保留。三个参数仍沿用原始变换：`mu = 3 × tanh(...)`、`alpha = softplus(...) + 0.1`、`guess = sigmoid(...)`。本轮没有把骨干换成 GRU，也没有额外加入 2PL 输出、新投影层或锚定正则。

方向二的 `aligned` 与 `static` 的模型结构完全相同，只在训练损失中增加一项：

```text
总损失 = 作答预测 BCE + 0.05 × 可靠性加权 Huber 难度对齐损失
```

教师先使用训练集作答，按 Rasch 形式 `P(答对) = sigmoid(学生能力 − 题目难度)` 联合估计训练学生能力和训练题目难度。这样会考虑“答这道题的学生整体水平如何”，而不是直接把答错率当作难度。拟合完成后固定教师，将观察到的训练题目难度标准化，再要求语义模型预测的 `mu` 靠近它；每题权重为 `n / (n + 20)`，作答较少的题影响更小。教师中的 ID 用来归并作答、拟合临时标量，部署时不把这张学生或题目参数表作为输入；冷题参数仍由语义产生。

**AUC 结果如下。** 表中为三个训练种子的均值 ± 样本标准差；AUC 以百分比表示，增量以百分点表示。

| 协议 | 原始 Transformer/AKT | 方向一：static | 方向一 + 二：aligned |
|---|---:|---:|---:|
| warm：常规学生留出 | 79.2231 ± 0.0256 | **79.4286 ± 0.0050** | 79.3792 ± 0.0272 |
| cold：题目也完全留出 | 73.5211 ± 0.2447 | **73.8001 ± 0.2420** | 73.6872 ± 0.3783 |

方向一相对原始模型，warm 平均增加 **0.2056 个百分点**，cold 平均增加 **0.2790 个百分点**。两个协议下的三个种子都为正。不过，cold 的种子 42 只增加 0.0112 个百分点，各种子的幅度差异也较大，所以目前适合说“观察到小幅提升”，还不能说效果显著或普遍稳定。

方向二相对已经加入方向一的 `static`，warm 平均减少 **0.0495 个百分点**，三个种子均下降；cold 平均减少 **0.1129 个百分点**，两个种子下降、一个种子上升。因此，这一版固定系数为 0.05 的难度对齐，**没有证明能够继续提高 AUC**。`aligned` 相对原始模型的平均 AUC 仍较高，不能把这部分合计增量全部归功于对齐。

| 协议 | 同种子比较 | 平均 AUC 增量 ± 样本标准差 | 种子 42 | 种子 2026 | 种子 3407 |
|---|---|---:|---:|---:|---:|
| warm | static − original | +0.2056 ± 0.0291 | +0.2034 | +0.1776 | +0.2357 |
| cold | static − original | +0.2790 ± 0.2907 | +0.0112 | +0.5882 | +0.2378 |
| warm | aligned − static | −0.0495 ± 0.0224 | −0.0727 | −0.0478 | −0.0279 |
| cold | aligned − static | −0.1129 ± 0.1680 | −0.2015 | −0.2179 | +0.0808 |
| warm | aligned − original | +0.1561 ± 0.0448 | +0.1307 | +0.1298 | +0.2078 |
| cold | aligned − original | +0.1662 ± 0.3098 | −0.1903 | +0.3702 | +0.3186 |

**难度对齐做到了它的部分目标，但这个目标与 AUC 不完全相同。** 在独立测试学生作答拟合的 Rasch 难度参照下，`aligned` 的语义难度排序与参照更接近。warm 的平均 Spearman 从 **0.8984 提高到 0.9273**；cold 从 **0.5142 提高到 0.5525**。两个协议下三个种子均提高；限制为每题至少 30 次参照作答时，三个种子的改善方向也一致。

此外，cold 中加入对齐后，平均 NLL 从 **0.6034 降到 0.6009**，Brier 从 **0.2082 降到 0.2075**，ECE15 从 **0.0419 降到 0.0308**，这些指标均以更低为好。NLL、Brier 衡量概率预测质量，ECE15 衡量分箱后的概率校准误差。也就是说，对齐后给出的概率在这些平均指标上更合适，但区分“谁更可能答对”的排序能力没有同步提升。不能因为 AUC 没涨就认定对齐毫无作用，也不能用这些指标替代 AUC 增益。

这里有两套严格分开的难度参照：**训练教师只看训练学生、训练题目的作答**；上述难度诊断的测试参照，是全部 18 组训练及权重选择结束后，另用独立测试学生作答拟合的。测试参照从未进入训练损失、调参或权重选择。cold 的诊断参照只纳入训练题目及测试冷题，排除验证冷题，相关性只计算 143 道测试冷题。Rasch 参照仍是静态、单维假设下的行为代理，相关性提高不能单独证明真实心理测量参数有效，也没有验证区分度和学生能力参数。

**本轮证据的适用范围。** 原始 AKT 的能力 `theta` 仍会以当前题目作为查询条件，题目参数也仍参与交互门控。因此，本轮能支持“使题目参数不随位置与历史变化”的实现与实验结果；不能据此写成“学生能力与题目属性已经完全解耦”，也不能保证完整模型满足经典 IRT 的全局单调性或参数可识别性。

warm、cold 都采用 2,950 名训练学生、492 名验证学生和 1,476 名测试学生。cold 使用一次固定的题目划分：663 道训练题、142 道验证冷题、143 道测试冷题；全部冷题作答都不进入训练或评估历史。三种子重复的是训练随机性，不是重新划分冷题；均值和标准差也不是显著性检验或置信区间。warm 测试学生划分曾用于此前项目开发，本轮不用于训练或选权重，但并非从未查看过的全新外部测试集。

**本轮没有达到 81%。** 本轮 warm 单次最高 AUC 为 `static`、种子 3407 的 **79.4342%**。之前保留的 **80.6453%** 来自另一套三模型集成，最终训练学生数、模型形式及评估历史窗口规则都不同；不能用本轮分数与它相减，解释为同一设置下的升降。本轮回答的是“这两个改动放回原始 Transformer 是否有效”。

**结果与权重在哪里。** 完整数值及核验记录见 [18 组正式结果](transformer-irt.md)、[机器可读结果与哈希](transformer-irt.json)、[难度诊断](transformer-difficulty.md)及[难度诊断 JSON](transformer-difficulty.json)。模型、数据和选择规则在训练前固定，见[本轮实验方案](../transformer_experiments/PLAN.md)。

本地权重保存在 `runs/transformer-irt-20261013/<协议>-<模型>-s<种子>/`，例如 `warm-static-s3407/`、`warm-aligned-s42/`。每个目录的 `best.pt` 是仅按验证 AUC 选出的权重，`config.json` 保存训练配置，`epochs.jsonl` 保存过程，`summary.json` 保存结果，`test_predictions.npz` 保存测试预测。权重和逐条预测不上传 GitHub，公开仓库提供代码、配置说明和汇总报告。

已经重新加载 `warm-aligned-s42/best.pt` 做过 GPU 推理核验：**415,735 条测试预测逐位一致，最大绝对差为 0，AUC、ACC、NLL、Brier、ECE15 均完全一致**。这是保存权重的推理复现，不是重新训练，也不承诺不同设备或重新优化过程逐位一致。证据见[权重推理复现记录](transformer-reproduction-warm-aligned-s42.json)。

在已配置好的 WSL Ubuntu-24.04 登录 shell 中，可直接检查已有权重和重新生成汇总，无需重新训练：

```bash
cd /mnt/d/doc/knowledge_trace_graduation_project/dlkt-research

/home/ml/.venvs/pytorch/bin/python tools/summarize_transformer.py \
  --root runs/transformer-irt-20261013 \
  --output reports/transformer-irt

/home/ml/.venvs/pytorch/bin/python tools/reproduce_transformer.py \
  --run-dir runs/transformer-irt-20261013/warm-aligned-s42 \
  --data-root dataset/NIPS2020 --device cuda \
  --output runs/transformer-irt-20261013/warm-aligned-s42/reproduction-check-2.json
```

复现工具会先核对当前代码、输入数据、协议、配置和权重哈希，再加载选定权重推理。输出文件必须使用尚不存在的名字，重复检查时更换 `--output` 文件名即可。读取现有报告、配置或权重不需要启动训练入口。
