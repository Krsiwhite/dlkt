# 纯语义知识追踪：解耦与难度对齐实验

本分支从 `baseline/local-original-20261013` 出发，保留原始 `TextAKT3PL` 作为参考，验证开题报告的两个方向。完整预设方案见 [PLAN.md](PLAN.md)。**实验是否有效取决于结果，不能把新增模块直接写成已得到验证的创新。**

## 改了什么

| 模型 | 题目属性 | 学生状态 | 预测方式 | 用途 |
|---|---|---|---|---|
| original | 原有语义、位置、题目上下文共同产生 μ/a/c | 原 AKT，受目标题查询影响 | 原 3PL 形式 | 原始项目参考 |
| semantic_mlp | 共享语义投影 | GRU 编码过去交互 | MLP | 同骨干对照 |
| decoupled | 当前题目、知识点语义独立产生 b/a | GRU 编码过去交互，生成标量 θ | sigmoid(a(θ−b)) | 方向一 |
| aligned | 与 decoupled 相同 | 与 decoupled 相同 | 同一 2PL，加训练难度辅助损失 | 方向一＋方向二 |

输入始终为原始 256 维题目向量和 256 维知识点向量。题号只用于固定向量查表和划分审计，不进入可训练 ID 表。共享投影层可以训练，原始向量不可训练。

新题参数分支不接位置或学生历史，因此同题跨学生、位置的参数一致。能力分支先编码已发生交互，再将状态右移一位，当前题目和当前答案均不能进入当前 θ。原始 AKT 与新 GRU 有骨干差异，因此不能用二者的差值单独证明“解耦”的效果；主要对照是相同 GRU 的普通头与 2PL 头。

## 难度对齐具体做法

1. 只用训练学生、训练题目的响应拟合一个固定斜率的正则化 Rasch 模型；将学生平均能力约束为零。
2. 对训练题目估计难度标准化，作为共享语义难度头的辅助目标。
3. 用 `n/(n+20)` 作为样本量可靠性权重；使用 Huber 损失，固定系数 0.05。
4. 推理时只由语义预测题目难度，不读取训练题参数表，也不利用新题的作答统计。

教师的学生/题目参数仅用于训练监督，并非部署模型的输入。这是“语义输入、行为监督”，不能表述为“完全不需要响应数据学习”。标准化和弱锚定不能证明心理测量参数真实或完全可辨识。

## 评测边界

- 学生训练/验证/测试分别为 2950/492/1476；验证集选权重，测试集不参与选轮或调参。
- 严格冷题另外划出 663/142/143 道训练/验证/测试题；冷题作答不进入任何历史。测试题有 63,732 个目标，每个目标只计一次。
- 常规测试采用长度 201、步长 100 的分块重叠历史；冷题使用最多 200 条历史训练题作答。训练每轮各目标仅计一次。
- 原有 80.6453% 是另一个三模型集成，使用不同训练和评测窗口方案。不能直接把这里的分数差当作新方法相对该集成的改善或退步。
- 当前沿用的学生测试分组在项目历史中已被使用；此次从训练与选择流程中隔离，但并非从未查看过的外部测试集。
- 本实验遵循 `used.txt` 中的既有序列顺序；若论文需要保证真实时间顺序，应另核查上游原始时间字段与预处理来源。

## 文件与运行

- `data.py`：数据划分、固定向量表、严格冷题窗口与目标覆盖审计。
- `models.py`：四种模型与可检查的题目参数、能力接口。
- `teacher.py`：训练集 Rasch 标定与对齐损失。
- `run.py`：训练、验证选模、最终测试与配置/指纹记录。
- `../tests/`：因果性、冷题隔离、参数不变性、难度监督、AUC 和评分顺序测试。
- `../runs/`：仅本地保存最佳权重、每轮日志、预测和输入指纹；Git 忽略此目录。

现有 WSL 的 Python 环境已含 PyTorch/ROCm，无需重新生成向量或安装另一套 GPU 环境：

```sh
python -m unittest discover -s tests -v
python -u -m experiments.run --output runs/round1-s42
python -u -m experiments.run --output runs/round1-repeat --variants decoupled aligned --seeds 3407 2026
python tools/summarize_experiments.py --roots runs/round1-s42 runs/round1-repeat --output reports/round1
python tools/reproduce_experiment.py --run-dir runs/round1-s42/warm-aligned-s42 --data-root dataset/NIPS2020 --device cuda
```

在其他机器使用 Python 3.10 及以上、NumPy、与硬件适配的 PyTorch 即可运行实验模块。仓库原有 `pyproject.toml` 是历史预处理环境说明，不是本实验的完整环境锁；具体已运行版本保存在每轮 `environment.json`。CPU 可用于性质测试和推理，完整训练建议用 GPU。

每次训练到达最佳验证 AUC 时保存 `best.pt`，每轮保存 `latest.pt`。中断运行不会自动混入新实验；不完整输出目录会拒绝覆盖，需要使用新输出目录。`latest.pt` 保留模型、优化器与调度器状态，但当前未提供严格随机状态恢复的续训功能。

跨种子实验复用第一组的 `warm-teacher.pt`、`cold-teacher.pt`，确保辅助监督目标完全一致。复现工具先核对数据、代码、配置和权重指纹，再加载已有权重推理；它验证的是权重推理复现，不是完整重训复现。汇总工具只读取已完成的实验，并逐项核对配对比较的测试目标。
